01 / System shape

One Laravel app, several AI labs

Larvis Agent is a single web application with a Laravel backend and an Inertia-powered React frontend. Laravel owns routes, validation, AI calls, persistence, and authentication. React renders each page and submits user actions back to Laravel.

The product surface is called Editorial Lab. It demonstrates content analysis, prompt experimentation, multi-turn chat, tool calling, and streamed responses. The “lab” framing is useful: these are feature demonstrations inside one app, not separate services.

Browser requests a route
Laravel renders an Inertia page or invokes a controller
Controller validates input and calls an agent
Agent calls a configured model and optional tools
Laravel returns JSON, a stream, or page props
React displays the result; selected workflows save it
Key boundary: controllers coordinate HTTP and storage; agents define model behavior; tools perform structured actions; React pages own interaction and presentation.

03 / Browser to backend

Request lifecycle

  1. Routing: bootstrap/app.php registers web and API route files, console commands, and /up.
  2. Middleware: web requests append TrackGuestDevice, HandleInertiaRequests, and asset preload handling. The first records guest device context; the second shares app name and current authenticated user with Inertia.
  3. Page response: routes use Route::inertia or a controller's Inertia::render. Laravel returns the root Blade shell on the first visit.
  4. React boot: resources/js/app.tsx resolves the page from resources/js/pages; AppLayout supplies navigation and auth UI.
  5. Action request: the page posts data, Laravel validates it, calls an agent, and returns JSON or a stream. The page renders the result. 
routes/web.php → controller → Agent::prompt() / Agent::stream() → provider
                                      ↓
                           JSON / Inertia / stream
                                      ↓
                                React page

05 / Feature walkthrough

Five AI workflows

Content Analyzer

AnalyzeContentController → StructuredContentAnalyzer → CategorizedPost (optional)

Requires at least 20 characters. The agent asks for a title, category, one-sentence summary, and tags. The controller turns the structured result into JSON. The web save action writes it to categorized_posts. API variants also demonstrate the tool-enabled ContentAnalyzer and queued processing.

Prompt Playground

PromptPlaygroundController → PromptPlaygroundAgent → PromptPlaygroundEntry

The page receives default settings and model choices. POST validates prompt, tone, length, temperature, top-p, and model profile. The agent uses Groq; tone and length affect instructions, length also selects a token cap, and a model profile can override the default. Each run stores prompt, response, provider, resolved model, and settings.

Conversation Lab

ConversationLabController → ConversationLabAgent → Laravel AI conversations

The page loads the latest thread for its participant. A POST accepts a message and optional UUID. An ID continues an existing conversation; otherwise a new one is created for the user. Logged-in requests use the authenticated user. Guests currently share a fallback user with email conversation-lab@example.com, so guest histories are not isolated by browser. The SDK conversation tables persist messages.

Tool Lab

ToolLabController → ToolLabAgent → AudienceSnapshotTool + CallToActionTool

Validates prompt, audience, and goal. Instructions ask the model to retrieve audience guidance and use CTA guidance when relevant. Response includes the final copy and tool call/result diagnostics. This workflow does not persist its generated answer.

Streaming Lab

StreamingLabController → StreamingLabAgent → StreamingLabEntry

Validates a prompt and streams model output. A completion callback saves the full text plus provider and model. This returns a stream instead of waiting to send one completed JSON response.

06 / AI SDK design

Agents and tools

Agent classes use Laravel AI SDK contracts and Promptable, keeping model instructions and capabilities outside HTTP controllers.

ContentAnalyzer

Tool-enabled editorial analyzer with SavePostTool. Its structured schema is declared, but current analyzer endpoints use the separate StructuredContentAnalyzer.

StructuredContentAnalyzer

Declares required title/category/summary/string-tags fields and shares editorial parsing instructions.

PromptPlaygroundAgent

Configurable tone, length, temperature, top-p, model and token limit. Uses Groq.

ConversationLabAgent

Groq conversational agent using SDK conversation memory.

ToolLabAgent

Groq agent with a four-step tool limit and two deterministic tools.

StreamingLabAgent

Groq agent with fixed generation settings and explicit model.

Tool behavior

  • SavePostTool creates a categorized post from structured fields.
  • SavePostImageTool generates and stores a banner, then records its path; it is currently commented out of ContentAnalyzer's active tools.
  • AudienceSnapshotTool returns fixed messaging guidance for founders, developers, or marketers.
  • CallToActionTool returns fixed signup, demo, or launch direction.

AnalyzesContent carries editorial instructions and a fallback parser for JSON or labeled text. Where the SDK returns structured output, controllers convert it directly to an array.

Provider configuration: prompt, conversation, tool, and streaming agents explicitly select Groq. StructuredContentAnalyzer does not specify provider/model in its class, so Laravel AI defaults determine them. Check config/ai.php and environment configuration for actual runtime values.

Application columns live in database/migrations. AI conversation tables are created with the SDK's AiMigration. Eloquent casts expose tags and metadata as arrays and generation parameters as decimal values.

08 / Identity

Authentication and guest devices

AuthController handles guest-only login and registration. Registration validates unique email and confirmed password; the User model hashes passwords. After login or registration, the controller associates a matching guest device if possible and regenerates the session. Logout invalidates the session and rotates the CSRF token.

TrackGuestDevice records unauthenticated web visits through Device::recordGuestVisit, keyed by session ID, then sets a one-year guest_device cookie when missing. Stored context includes IP, user agent, last-seen time, and current request path/method. Device::attachToUser matches guest UUID or old session ID when the visitor signs in.

Device tracking and AI conversation ownership are separate mechanisms. The current guest conversation fallback is one shared application user.

09 / React

Pages and shared UI

resources/js/app.tsx starts Inertia and maps server page names to components. AppLayout renders the Editorial Lab header, nav, and auth state from shared page props. Pages handle their own form state and output display. Wayfinder-generated helpers are imported from @/routes or @/actions; use them rather than composing URLs by hand.

Pages

AnalyzeContent, PromptPlayground, ConversationLab, ToolLab, StreamingLab, Login, Register and welcome.

Root view

resources/views/app.blade.php mounts the app and Vite assets.

Shared props

HandleInertiaRequests shares the app name and authenticated user.

Tailwind CSS styles the UI using the project editorial palette. resources/js/lib/utils.ts contains small shared class utilities.

10 / Runtime

Configuration and local work

  • config/ai.php plus environment variables select provider credentials/defaults. Keep real keys in local environment configuration.
  • config/database.php, config/queue.php, and config/session.php govern storage and background work.
  • vite.config.ts wires Laravel, React, Tailwind, and Wayfinder build support.
  • composer.json and package.json define dependencies and common scripts.
  • The project overview names a Herd URL of http://larvis-agent.test; local setup determines if it is available. 
composer run dev        # app, queue worker, Vite together
npm run dev             # Vite only
npm run build           # production frontend assets
php artisan route:list  # registered routes
php artisan test        # Pest / PHPUnit suite

Live AI calls need valid provider configuration. Tests should fake agents instead of contacting providers.

11 / Expected behavior

How tests give confidence

Feature tests in tests/Feature exercise routes and use Laravel AI fakes to check validation, response shape, model/provider selection, tool calls, and whether an agent was invoked. Current feature coverage includes auth, content analysis, conversation, prompt, streaming, and tool labs.

The analysis test fakes StructuredContentAnalyzer and asserts the tool-enabled ContentAnalyzer is never prompted. Tool Lab tests show how a tool call and result appear in the HTTP response. This guide is based on source reading; it does not claim that the suite was run.

12 / Explore a feature

A good reading order

  1. Read routes/web.php and routes/api.php to see the public surface.
  2. Choose a page such as resources/js/pages/ToolLab.tsx; follow its submit action to the controller.
  3. Read the agent to understand instructions, provider/model, and capabilities.
  4. Read tool classes to see side effects and deterministic behavior.
  5. Check the model and migration for persisted fields.
  6. Read the feature test to see the expected HTTP contract without a live provider.
